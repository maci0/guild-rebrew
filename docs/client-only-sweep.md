# Historical client/server sharing survey

The round-19 survey asked whether GoldTL bodies inside shared TU spans could be
retained by the server build then in use. Its classifications are historical;
they are not a current work queue or byte verdict.

Shared code does not imply shared allocations. Client command queues, renderer,
UI, sound and text data may have no server counterpart. Equal-offset neighbors
or a constant address shift do not prove storage correspondence.

Use current native calls, operands and [ownership evidence](data-ownership.md)
before sharing a body. [Source layout](source-layout.md) covers organization.
The full survey table, sizes, operand counts and inference limits are archived
and address-indexed below; its retired helper scripts are not current procedures.
