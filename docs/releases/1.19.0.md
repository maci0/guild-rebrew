# Guild Rebrew 1.19.0

2026-11-27 source reconstruction checkpoint. The validation records no gameplay or deployment tests.

Source and metadata only, no original game binaries or playable client build.

## Changes

- Function names: ten naming batches (n01 to n10) renamed 2,276 functions from evidence in the code. Function rows with source that still carry a generated `fcn_` name fell from 3,849 to 1,814 of 5,154 (GoldTL) and from 1,713 to 265 of 2,376 (Gold); the server has none. Each rename is in `docs/name-ledger.tsv` with its evidence class.
- Shared source files: `server.c`, `Error.c`, `sim.c`, `zufall.c`, `plant.c` and `aemter.c` are now one file each for all three targets. The client copies of their functions moved into them from single-function files, with edition guards where the bodies differ. Three Gold `vfs` functions moved onto `vfs.c`'s body, which matches as well or better at the Gold address.
- Cross-target type conflicts: 32 to 0.
- Server data: the gate's verification matches all 652 data records, including the C runtime records placed from the byte-identical raw link; all 547 records in `.data`, `.rdata` and `.bss` are `EXACT`.
- Metadata cleanup: two stray server function rows removed, five data rows repointed to the files that declare them after merges removed theirs, and two unbuilt dead source files removed.
- Rebrew pinned at 6.84.0 (was 6.81.1) in `pyproject.toml` and `uv.lock`. Project and lockfile version 1.18.0 to 1.19.0. Releases 6.81.2 to 6.84.0 carry fixes found while working on this project: identical-image data placement, `rebrew source rename-batch`, BinSync typedef export and underscore-name comparison, and support-file orphans.
