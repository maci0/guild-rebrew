# Guild Rebrew 1.18.0

2026-11-26 source reconstruction checkpoint. The validation records no gameplay or deployment tests.

Source and metadata only, no original game binaries or playable client build.

## Changes

- Gold twins of GoldTL functions. 51 Gold rows now share their GoldTL twin's C body and reach `RELOC` or `EXACT` with every byte matching and every relocation validated (17 `EXACT`, 34 `RELOC`); two rows already bound to those sources rose with them (one to `EXACT`, one to `RELOC`). Candidates came from `rebrew source import-related` between the two clients. Each was compared unbound first and bound only when fully proven. No stored status fell. [The provenance ledger](../provenance.md) lists every row.
- Naming for those twins: Gold and GoldTL now give one name to the globals and callees that 106 byte-matching Gold twins use. 87 of those twins still use names Gold does not resolve (compiler literals, CRT helpers, callees without a Gold row, globals typed differently in the two clients).
- Gold link repairs: eight placeholders that real Gold bodies now define are removed, and `spiel.c` no longer compiles the server body of `eval_ObjektPreis2Credits` into Gold (Gold 0x508820 is the GoldTL body).
- Rebrew pinned at 6.81.1 (was 6.79.0) in `pyproject.toml` and `uv.lock`. Project and lockfile version 1.17.0 to 1.18.0. 6.81.0 and 6.81.1 carry fixes found while working on this project: path-independent type evidence digests, replica divergence reporting, faster rebind and retire, unresolved-operand reporting for imports, unshare compiles without a Docker call once an image is exported, and source identities through a symlinked checkout path.
- Type evidence digests are stored in the path-independent form (`rebrew types migrate-context`), so a clone at any path lints clean.

- The CMake trees were configured again at the checkout's current path (`/home/maci/Projects/guild-rebrew`) with the options their earlier caches recorded, and rebuilt in full for this gate.
