## Quick Start

```
1. rebrew todo --json                          # get highest ROI action items
2. rebrew lib-match --lib <runtime>.LIB --va 0x<VA>   # is it already in a library?
3. rebrew skeleton 0x<VA>                      # generate .c skeleton
4. rebrew test src/server.dll/<func>.c --json  # compile + compare
5. # iterate code until STATUS: EXACT or RELOC
6. rebrew test --all --json                    # batch promote all ready functions
```

> [!IMPORTANT]
> **Do step 2 before reversing anything.** Statically linked library code sits
> in `.text` looking exactly like target code. Reversing it is wasted effort:
> the linker supplies those bytes anyway, and the result gets committed,
> counted as coverage, and "improved" for weeks before anyone notices it was
> never yours. Mark such functions `// LIBRARY:` and move on.
>
> `rebrew flirt` and `rebrew crt-match` are the fast first pass, but treat a
> miss as inconclusive rather than as "this is target code". FLIRT matches
> short byte patterns against prebuilt signatures, so a signature set built
> from a different library build misses real matches, and a decompiler names
> library code `fcn_XXXX` like anything else. Measured on one MSVC 6 project,
> FLIRT identified 9 of the 68 CRT functions actually present.
>
> `rebrew lib-match --lib <archive>` settles it: it compares whole function
> bodies against the archive the project links, masking each object's
> relocation slots, and indexes COFF static symbols too. Whatever is
> identical outside those slots is library code.

## Annotation Format

Every reversed `.c` file starts with a **stable identity header** — only the
information that is intrinsic to the function and never changes:

```c
// FUNCTION: server.dll 0x<virtual_address>
// SYMBOL: _function_name                 ← optional, derived from C definition

void __cdecl function_name(void)
{
    // stub
}
```

Volatile metadata (status, size, compiler flags, notes, blockers) is stored
**outside** the `.c` file in the project's single `rebrew-functions.toml`
(`cfg.metadata_dir`, one file for the whole tree):

```toml
["server.dll.0x10001234"]
status = "STUB"
size   = 42
cflags = "/O2 /Gd"
blocker = "register allocation"
note   = "inline asm detected"
```

> [!NOTE]
> **Progress lives in build output, not in the tree.** `rebrew build-db` writes one
> clear-text `db/coverage-<target>.toml` per target (functions, globals, verify rows,
> status history); the dashboards and the sibling `recovery` UI read those documents and
> nothing else. They are gitignored build output — regenerate them, never hand-edit them —
> and an older `db/coverage.db`, `db/data_<target>.json` or `db/*.csv` is stale: no reader
> globs it any more, so delete it (`rebrew lint` warns, W032).

> [!CAUTION]
> **Never manually edit `rebrew-functions.toml` or `rebrew-data.toml`.** They are managed
> exclusively by Rebrew CLI tools (`rebrew test`/`verify`/`prove` for STATUS;
> `rebrew blocker set/clear`, `rebrew diff --fix-blocker`, `rebrew near-diag --fix-blocker`,
> `rebrew document-unmatched` for BLOCKER; `rebrew data` / `rebrew sync` for globals).
> Every write goes through `rebrew.metadata` / `rebrew.data_metadata` (locked + atomic) —
> hand-edits bypass the lock and get clobbered.

**STATUS values**, strongest claim first: `EXACT` (byte-perfect) > `RELOC` (match after
masking relocations) > `NEAR_MATCHING` (close) > `STUB` (incomplete).  `PROVEN`
(semantically verified) is **not** a byte match and does **not** outrank `EXACT`: it ranks
**below** `RELOC`, because a proven function still compiles to bytes that differ from the
target (every PROVEN entry carries a non-zero delta).  PROVEN is not sticky: the next
`rebrew test`/`rebrew verify` records the byte result over it, and it must never be counted,
reported or labelled as byte-matched.

`CFLAGS` is optional — falls back to the target default from `rebrew-project.toml`.

## Compiler Constraints (msvc-6.0-sp5)

- **C89 only**: no `for(int i=...)`, declare all variables at block top
- **Comments in code**: use `/* */` only (C89). `//` is used exclusively for annotation headers
- **Symbol decoration**: `_func` for `__cdecl`, `_func@N` for `__stdcall`
- **No `/GS`** (buffer security), no `__declspec(noinline)`
- **Execution**: all CL.EXE/LINK.EXE calls run inside the toolchain's docker image (wine lives in the image; there is no host wine/wibo fallback)

## Linking

- **Link stock libraries. Never patch a `.lib`.** When a library object drags
  in something the reference does not have (an extra import, duplicate data),
  displace it with a local definition of the symbols it provides, or change
  what references it. A hand-edited library cannot be reproduced from a clean
  checkout, and it hides the duplication that library-detection depends on.
- **A duplicate-symbol warning is a finding, not noise.** `LNK4006` /
  `LNK4217` usually means either the same global is defined in several
  translation units, or you have reimplemented something the library already
  provides. Resolve it rather than silencing it with `/FORCE:MULTIPLE`; keep
  the flag only for cases you have identified and written down.
- **Compare the import table against the reference** after any link change.
  An extra import means a library object came in that the original did not
  have; a missing one means the opposite.
