 133|### File Naming Patterns
 134|
 135|- German nouns for gameplay concepts: `spiel` (game), `aemter` (offices),
 136|  `friedhof` (graveyard)
 137|- English for technical/infrastructure: `server`, `lobbycommands`, `loadsave`
 138|- Subsystem logic files get a `_logic` suffix: `alchemistry_logic`,
 139|  `friedhof_logic`
 140|- Shared library code lives under `Units\` with short module names:
 141|  `d3`, `net`, `vfs`, `Msx`, `m_alloc`
 142|
 143|## Module Prefix System
 144|
 145|Every exported/named function carries a **module prefix** identifying its
 146|subsystem:
 147|
 148|### Game Logic Modules
 149|
 150|| Prefix | Module       | Source File              | Domain                          |
 151||--------|--------------|--------------------------|---------------------------------|
 152|| `cm_`  | Command      | `command.c`              | Command validation & execution  |
 153|| `gm_`  | Game         | `spiel.c`                | Entity/object/building mgmt     |
 154|| `lb_`  | Lobby        | `lobbycommands.c`        | Network lobby layer             |
 155|| `ahm_` | Alchemy      | `alchemistry_logic.c`    | Alchemy subsystem               |
 156|| `gv_`  | Graveyard    | `friedhof_logic.c`       | Graveyard subsystem             |
 157|| `sim_` | Simulation   | `sim.c`                  | Citizen simulation              |
 158|| `amt_` | Offices      | `aemter.c`               | Office / election system        |
 159|| `ls_`  | LoadSave     | `loadsave.c`             | Save/load serialization         |
 160|| `plt_` | Plant        | `plant.c`                | Zone/record lookup, vegetation  |
 161|
 162|### Infrastructure Modules (`Units/`)
 163|
 164|| Prefix | Module       | Source File              | Domain                          |
 165||--------|--------------|--------------------------|---------------------------------|
 166|| `m_`   | Memory       | `m_alloc.c`              | Tracked heap alloc, pool alloc  |
 167|| `vfs_` | VFS          | `vfs.c`                  | Virtual file system, streams    |
 168|| `srv_` | Server       | `server.c`               | Server lifecycle, main loop     |
 169|
 170|Two units have **no attested prefix**: `Units/Error/Error.c` and
 171|`Units/net/broadcast.c`. The debug strings and the binary's own names for
 172|them are not recovered, so their functions keep descriptive unprefixed names
 173|(`LogMessageInternal`, `ReportFatalError`, `SendBroadcastPacket`) rather than
 174|an invented `err_`/`net_`. The string corpus confirms this: the only
 175|module-prefixed identifiers near `Error.c` (`0x10027144`) and `broadcast.c`
 176|(`0x10001130`) are asset names, and neither unit logs with a `err_*():` or
 177|`net_*():` prefix. Add a row here only when the original name is attested.
 178|
 179|File-scoped save/load helpers inside a module take a `fio_` (file I/O) infix:
 180|`amt_fio_LoadAemter`, `amt_fio_SaveAemter`. The prefix chain is
 181|`<module>_<role>_<VerbNoun>`, so `amt_fio_LoadAemter` is the `aemter.c`
 182|file-I/O loader.
 183|
 184|### Client-Only Modules (`Europa1400Gold*.exe`)
 185|
 186|The client binaries share the game logic (`cm_`, `gm_`, `amt_`, `ls_`, `gv_`,
 187|`ahm_`) but add engine subsystems that never appear in `server.dll`. These
 188|prefixes are attested by log strings in `Europa1400Gold_TL.exe` and
 189|`Europa1400Gold.exe` and are **out of scope for this repo's decompilation
 190|target**; they are recorded so names are not invented twice.
 191|
 192|| Prefix  | Module            | Domain                                   |
 193||---------|-------------------|------------------------------------------|
 194|| `ch_`   | Character         | Character/mesh/animation runtime         |
 195|| `ai_`   | AI                | Meister (master) AI decision routines    |
 196|| `he_`   | Handlungsereignis | Game events                              |
 197|| `cut_`  | Cutscene          | Cutscene control                         |
 198|| `d2_`   | Direct2D layer    | 2D UI/interface layer (`d2.v1`)          |
 199|| `d3_`   | Direct3D layer    | 3D renderer (`d3/`)                      |
 200|| `txt_`  | Text              | Text file parse/format                   |
 201|| `lc_`   | Location          | Building placement / jail queries        |
 202|| `rd_`   | Record            | Record / supermap lookup                 |
 203|| `sv_`   | Server view       | Client-side state sync                   |
 204|| `io_`   | I/O               | Generic file I/O                         |
 205|| `init_` | Init              | Startup / scene init                     |
 206|| `main_` | Main              | Client main loop / menus                 |
 207|| `nt_`   | Network           | Client network layer                     |
 208|| `ob_`   | Object            | Object behaviour on the client           |
 209|| `gs_`   | Court (Gericht)   | Evidence / trial system                  |
 210|| `am_`   | Method registry   | Engine method registration (`am_RegisterMethod`) |
 211|
 212|Assets, script commands, and config keys in the client also use `prefix_`
 213|spellings (`bau_`, `bk_`, `sp_`, `ub_`, `upgr_`, `riss_`, `prva_`, `snd_`,
 214|`sbs_`, …). Those are data identifiers, not function names; do not map them
 215|onto C symbols.
