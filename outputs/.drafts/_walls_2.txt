  49|### 2. `msvc6` merges byte-identical early-return epilogues unconditionally
  50|
  51|The reference **does not merge**. On `gm_FindNextFilteredEntity` (0x10016f80) it keeps **five
  52|`ret` sites**: three byte-identical short epilogues (`xor eax,eax; pop esi; ret` at `+0x17`,
  53|`+0x27`, `+0x75`) and two byte-identical long ones (`+0x141`, `+0x155`). Each short one is
  54|reached by a **2-byte** conditional jumping *over* an inline fall-through return. Our `/O2`
  55|object keeps **two** `ret` sites with five `rel32` branches into one shared block.
  56|
  57|The cross-jump is therefore **not** downstream of any difference between the exits — they are
  58|byte-identical in the reference and it still does not merge them. Proof that it is not a shape
  59|problem: a 352-byte standalone TU carrying the target's exact guard/loop structure reproduces
  60|the reference's *prologue byte-for-byte* and still folds all three exits. `/O1`, `/O2 /Os`,
  61|`/O2 /Og-` and `/O2 /Ot /Oy-` all fold too.
  62|
  63|**Eight return spellings have been compiled across two passes and all are inert.** This is the
  64|wall behind the recurring "the reference keeps N epilogues and we keep one" note in this
  65|project's file headers (`msvc6-c-shapes.md` §74).
  66|
  67|### 3. The `volatile` idiom has a direction, and a per-site wall
  68|
  69|`volatile` on a 16-bit load selects `mov r16,[mem]; and r,0xffff`; a plain load selects
  70|`xor r,r; mov r16,[mem]` (`msvc6-c-shapes.md` §52). **The direction is easy to get backwards** —
  71|one pass was briefed with it inverted and spent 14 probes refuting the brief, not the mechanism.
  72|
  73|Where the reference's form is the *masked* one, the lever is to remove the qualifier — and that
  74|can be impossible, because the qualifier is often what holds the loop's register allocation.
  75|On `gm_AllocSpieler` dropping it at the sympathy-loop reads produces exactly the reference's
  76|local form and costs **362 matched bytes** (736 -> 374). Sweeping the qualifier *in* is worse
  77|still: 736 -> 488/408/365 at 1/8/17 sites, and the full sets exceed the composition band.
  78|
  79|Corollary that invalidated an earlier inventory: `and r,0xffff` site counts are **not** a length
  80|signal. On that function both sides' real code is already exactly 3689 bytes, the gap curve
  81|oscillates ±48 and returns to 0, and all four reference `xor`s are present — the "6 extra `and`,
  82|4 missing `xor`" figure three passes worked from was a fixed-offset artefact.
  83|
  84|### 4. Address folding and strength reduction
  85|
  86|- **`base + idx` always folds to one `[reg+reg]` operand.** Nineteen spellings on
  87|  `gm_AllocGebaeude` — pointer cast, array subscript, two-step pointer, `idx << 6`, `(unsigned)`
  88|  cast, `int*`-scaled, `&arr[..]`, named intermediates, split across two statements — all emit
  89|  `mov cl,[eax+ebx]` (shapes §73). Confirmed at a **second** site on
  90|  `gm_CheckInventoryCapacity`. Materialisation can be forced by giving the address a second
  91|  read, but that flips `entity_index`/`in_list` (edi->esi, ->edi), moves `push edi` by 0x27 bytes
  92|  and adds 7 instructions: one decision, not two.
  93|- **`add R,R` where the reference has `lea R,[R+R]`** (4 sites on `gm_AllocSpieler`, 1 byte
  94|  each) — strength reduction follows the value's *uses*, not the spelling (Finding 54).
  95|- **FPU operand forms**: the reference emits `fsubr qword [const]` directly where we emit
  96|  `fld qword [const]` then `fsub st(1)`, plus an extra `fstp st(0)`. On `gm_AllocSpieler` the
  97|  two largest hunks (+160, +144) sit here, alongside a hoisted `slot+0x124`/`slot+0x128` FPU
  98|  block that our object computes *before* the 14-iteration loop where the reference computes it
  99|  after — ~8 instructions moved across the whole loop.
 100|- **A constant-0 register CSE** on `CrashDump`: the reference emits `push 0` 49 times (2 bytes);
 101|  we emit `xor edi,edi` once plus 31 extra `push edi` (1 byte), −26 bytes of push encoding.
 102|  Spelling the zero as `(LPOVERLAPPED)0`, `NULL`, `(void*)0`, `(DWORD)0` is byte-identical — a
 103|  register-allocator value choice, not reachable from C.

 105|### 5. Flags are not a general lever
 106|
 107|`#pragma optimize("a", on)` is a real lever at *specific* aliasing sites (shapes §44) but it
 108|does not generalise: on `ahm_ExAllocAlchemist` it collapses the function (matched 714 -> 480,
 109|object 1008 -> **1024**, past the admissible band) and `"w"` regresses (475); on
 110|`cm_ExProdObjekt` it collapses 888 -> 279 and `"w"` regresses 871 with 22 diffs; on
 111|`vfs_OpenStream` `"a"` gives 390 -> **83** with the object at 720 (tables moved). In every case
 112|it also leaves the composition band, so it fails on layout as well as score.
 113|`/Ot /Oa /Os /Og- /G6 /Oi /Ob1 /G5 /Ow` have been swept repeatedly on the large functions with
 114|no win (`/G6` crashes to 135 at object 1056).
