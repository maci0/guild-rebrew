## What It Does (High Level)

Large initialization / configuration routine.

Notable behaviors:

- Copies three incoming parameters into globals at `0x10034610`, `0x10034614`, `0x10034618`.
- Derives a 1-bit flag from the third parameter: `((arg2 >> 4) & 1)` and stores it at `0x1003461c`.
- Stores a pointer argument into `0x117660e0`.
- Calls several helper routines (some via IAT indirection), builds/initializes a couple of stack buffers, and emits/logs data.
- If `(BYTE)0x10034618 & 1` is set, iterates a table at `0x10027084..0x100270e4` in 0x20-byte steps, performing work per entry.
- Optionally (if `0x10034618 & 8`) calls two IAT functions and stores a result to `0x11766204`.
- Always performs a final log/dispatch loop over a dword table at `0x10027078..0x10027084`, calling `fcn_10002640` for each entry.

## Notes

- Byte-identical assembly is stored in `rebuild/asm/_fcn_10003320.asm` and verified against `rebuild/asm/_fcn_10003320.bin`.
- This function includes many relative `call rel32` instructions; `rebuild/asm/_fcn_10003320.asm` uses `org 0x10003320` so NASM computes the same displacements as the original binary.
- Encoding quirks: MSVC6 sometimes chooses alternate opcode forms for register-register `mov` (e.g. `8B F0` vs `89 C6`), so the `.asm` uses a couple of 2-byte `db` sequences to preserve exact bytes.
